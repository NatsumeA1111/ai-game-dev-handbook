# 与统一素材库对接

本知识库管选择、导入、验证流程；素材库管包及其来源、许可、依赖、版本；游戏仓库管实际消费记录。不要复制第二份 manifest 标准。

对接对象为 `game-asset-library`。协议审阅基线为该库 PR #1 提交 `353db039cb8f61170ec8e1d8e8ae89e113d69e73`，当时尚未合并。该库是私有库；无权限时报告不可读取，不冒称不存在。用前重新检查目标 ref，不假设主分支已有规范。

1. 从游戏档案确认引擎精确版本、平台和美术用途，再读素材库该 ref 下的 `docs/consume.md`、`docs/fields.md`、`catalog/index.json`。索引为空就没有已收录可用包，模板不计素材。
2. 核对所选包 manifest、LICENSE、README、依赖闭包和预览。`ready` 不代表允许再分发；每个包及依赖都要满足本次用途的许可。授权未知就停用该包，不自行补许可证。
3. 使用固定提交的包，在隔离目标工程验证。保留 Cocos `.meta` / UUID 及依赖闭包；发现碰撞不静默覆盖、不随意重写 UUID。禁止依赖旧游戏的绝对路径或运行时私有目录。
4. 完成干净导入、实际加载、最小场景运行及目标平台必要检查；文档/JSON 校验不是引擎验收。没有 Cocos 或授权环境就标阻塞，不升级状态。
5. 用素材库 `templates/consumption-record.md` 在游戏里记录包 ID、版本、upstream commit、导入文件、依赖、许可、局部改动和证据；更新先比差异，不能覆盖游戏内本地修改。

素材库内 `template/draft/docs-checked/import-checked/runtime-checked/ready` 与本库知识评估分级各自独立，不机械映射。现阶段是对接规范，不是已完成资产导入的实测证明。抽取或发布素材另按用户明确授权执行。
