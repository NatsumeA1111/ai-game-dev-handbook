# 存档与事务回归

状态：候选技能。提炼自真实浏览器存档迭代与失败记录，见 [来源与边界](../../../knowledge/practice-evidence.md)。尚无跨项目技能试用。

读取项目 AGENTS.md、存档协议和项目档案。先确认承诺是刷新恢复、进程重启还是更强耐久；不要将一个项目的 IndexedDB/Web Locks 方案强制用于原生或小游戏。没有隔离环境就只审查，不碰真实用户档。

1. 新建专属测试 profile/namespace，保留旧数据原字节。列状态不变量：余额、已领取奖励、固定候选、事务 ID、revision、模拟时间、待处理交互；按当前项目取舍，不凭空增加业务规则。
2. 明确真正提交点。Web 异步事务的 request success 不等于 transaction complete；写后读回也不等于断电落盘。已提交与待提交状态分开，不向用户暴露尚未提交的新结果。
3. 覆盖正常提交、写前失败、写后响应丢失、重复点击、同一 pending 重试、并发写者。失败后不得再次随机或重复扣款；已提交但响应丢失应可确认同一结果。使用模拟交易，非真实支付。
4. 恢复覆盖刷新、正常关闭、背景/前景、恢复等待及明确继续；等待期检查时间和输入不自行推进。若要测强杀，只能针对明确由本次测试创建的隔离进程，先验证归属，不关闭用户浏览器。
5. 迁移使用合法旧档副本并校验原字节未变；坏档、未知版本、缺字段分别测。普通可选字段可默认，奖励资格、计数、时钟等必须满足业务不变量；无法安全迁移就保留原数据并明确拒绝，不能静默清档、新局或退旧版本。
6. 独立记录进程终止方式、提交与观察的先后、重复次数和关键状态。正常关闭可能额外提交，不能把合法版本增加当丢失。对同一检查点多次恢复，不宣称测了多个独立交易。

执行项目适用测试、类型检查、真实运行；保存原失败及负面证据。用 [验证记录](../../../templates/verification-record.md) 区分逻辑原子性、实际浏览器进程恢复、断电、跨设备及原生平台。未测的耐久不作承诺；无法复现可加固但不关闭原缺陷。结束只清理本次资源，不删除旧档。
