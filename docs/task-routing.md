# 按任务进入，不重跑整个开发阶段

先读目标游戏的 AGENTS.md 与项目档案。档案是环境事实，不是授权书；当前用户任务及适用安全约束决定可做什么。未知项只有阻塞本次动作时才询问，其余记为未测。

| 本次任务 | 起点与必要证据 | 何时需要用户决策 |
| --- | --- | --- |
| 新玩法或关键假设未定 | 小范围原型，先写假设与退出条件 | 核心范围、取舍、是否进入量产 |
| 已确认功能 | 现有工程最小改动→定向测试→相关回归 | 超出范围或验收目标冲突 |
| 可复现缺陷 | 同环境复现→修复→同场景回归 | 无法安全复现、需破坏性数据操作 |
| 无法复现缺陷 | 保留环境和失败次数，增加观测或防御性加固 | 需要新访问权限；不能把加固当原问题已修复 |
| UI/适配修复 | 原界面+视口矩阵+交互及状态不变量 | 改美术方向或交互语义，而非单纯修裁切 |
| 存档/奖励事务 | 隔离数据、提交边界、失败重试/迁移矩阵 | 数据丢弃、兼容性取舍、修改真实存档 |
| 角色设计/动作 | 已认可母稿与项目模型合同→单动作质检→真实尺寸/引擎验证；使用 [角色动作技能](../.agents/skills/character-motion-pipeline/SKILL.md) | 新增生成预算、改母稿方向、正式替换或批量扩展 |
| 素材复用 | 包来源/许可/固定版本→干净导入→运行 | 授权不明、依赖冲突、需要付费或公开分发 |
| 发布 | 目标构建、真机范围、许可和回滚检查 | 发布目的地与发布动作本身需获得授权 |

原 SOP 的阶段放行指项目阶段或实质性方向变化，不是每个内部技术步骤都暂停。已经授权的小任务可连续完成开发、测试、修复、再测试；不要为固定需求另造 demo。不得借此绕过用户明确要求的审核点。批准改代码不等于批准安装、推送、合并或发布；分别按任务已有授权执行。

停止条件：验收通过；同一失败两轮无新增证据则总结并换调查方向；权限、不可恢复数据或关键产品取舍超出范围则停相关动作，其余独立工作继续。不可通过删测试/改验收线来取得通过。

每次交付用 [证据记录](../templates/verification-record.md)，注明通过、失败、阻塞、未运行。仅文档修改不需要游戏全量真机验收；影响存档、输入、布局的变化补相应回归。
